# 06. 최종 결과물

> 서식4의 **최종 결과물** 단계다. 형식과 규칙은 [README.md](README.md)에 있다.

제출 직전에 쓴다. **앞의 01~05를 읽고 요약하는 문서다.** 여기서 새로 지어내지 않는다.

## 들어갈 것

### 1. AI를 어디에 썼는가

**결과물에 들어간 것** — 배포되는 산출물의 구성이다.

| 주체 | 결과물에서 맡는 것 |
| --- | --- |
| ChatKHU | 사용자가 읽는 모든 문구, 확장 프로그램 아이콘 — 생성물이 배포본에 포함된다 |
| Jev 1.13 | 기사·제목·문장 판단 — 실행 중 호출된다 |
| 코드 | 점수 합산, 배지 단계 결정, 출처 도메인 대조 |

**과정에만 쓴 것** — 결과물에 남지 않는다. ChatKHU가 아니므로 사유가 필수다.

| 주체 | 한 일 | 사용 사유 |
| --- | --- | --- |
| 코딩 도구 | 구현·테스트·측정 스크립트·리뷰·문서 | 아래 본문 2절 |

### 2. 외부 도구를 쓴 사유

ChatKHU가 아닌 도구를 쓴 경우를 모아 적는다. 각 항목의 근거는 01~05에 이미 있으므로 요약하고 링크한다.

### 3. 사람이 결정한 것

01~05에서 **"사람이 결정·수정한 것"** 칸을 모은다. 특히 AI 제안을 버린 결정.

### 4. AI가 하지 않은 것

- 점수 합산과 배지 단계 결정 — 코드가 한다 ([../jev.md](../jev.md) 3절 ②)
- 사용자에게 보이는 문구의 최종 확정 — 사람이 검토한다
- 출처 도메인 판단 — 코드가 목록과 대조한다
- 판단 항목 선정의 최종 결정 — 사람이 한다

### 5. 한계

- 한국어는 Jev의 주 학습 언어가 아니다 ([../jev.md](../jev.md) 4절)
- 모델이 적대적 입력에 흔들릴 수 있다 ([../jev.md](../jev.md) 3절 ⑥)
- 우리는 진위를 단정하지 않는다. 이것은 한계이자 설계 의도다 ([../product.md](../product.md) 2절)
- 평가 세트 정확도 수치 미산출 — 아래 본문 5절

### 1. AI를 어디에 썼는가

**결과물에 들어간 것** — 배포되는 산출물의 구성이다.

| 주체 | 모델 | 결과물에서 맡는 것 |
| --- | --- | --- |
| **ChatKHU** | `gpt-5.6-luna`, `claude-sonnet-5-5` | 사용자가 읽는 **모든 문구**(18차에 걸쳐 생성), 확장 프로그램 **아이콘** |
| **Jev** | `jev-1.13.0` | 기사·제목·문장 판단, 리포트의 기록 대조 — **실행 중 호출된다** |
| ChatKHU 게이트웨이 경유 | `sonar-pro` | 리포트의 주변 기록 검색 — **찾기만 한다. 판정하지 않는다** |
| ChatKHU 게이트웨이 경유 | `claude-opus-5-5` | 리포트의 글 엮기 — **판정하지 않는다** |
| 코드 | — | 점수 합산, 배지 단계 결정, 출처 도메인 대조, 날짜 비교, 생성물 거르기 |

사용자가 읽는 글자는 **한 줄도 코딩 도구가 짓지 않았다.** 실행 중에 생성되는 유일한 한국어는 리포트의 요약 문단이고, 그것조차 코드가 그 자리에서 거른다 — 우리가 보내지 않은 문장, 금지어, 마크업이 들어 있으면 **고치지 않고 통째로 버리고** 미리 써 둔 문구로 대신한다.

**과정에만 쓴 것** — 결과물에 남지 않는다.

| 주체 | 한 일 | 사용 사유 |
| --- | --- | --- |
| 코딩 도구 (Claude Code / Claude Opus 5) | 구현, 테스트, 측정 스크립트, 코드 리뷰, 문서 | 저장소를 읽고 명령을 돌려야 하는 작업이다. ChatKHU의 역할(판단 기준 설계, 사용자 노출 문구 작성)이 아니다 |
| 웹 검색 | 가상 기사의 고유명사가 실존하는지 확인, 공식 문서 교차 확인 | 생성이 아니라 조사다 |

### 2. 외부 도구를 쓴 사유

대회 규칙상 ChatKHU가 아닌 도구는 사유를 적는다. 유형은 셋뿐이다.

| 유형 | 사유 | 해당 기록 |
| --- | --- | --- |
| **구현·테스트·측정** | 저장소를 읽고 빌드·테스트를 돌려야 한다. 생성이 아니라 실행이다 | [03](03-design.md), [04](04-build.md), [05](05-test.md) 전반 |
| **공식 문서 조사** | Chrome 확장 API·Cloudflare·npm 레지스트리에서 **권한이 실제로 필요한지, 바인딩이 실제로 어떻게 도는지** 확인했다 | [03-design.md](03-design.md) |
| **ChatKHU 키가 없는 환경** | 라벨링 기준 초안을 코딩 도구로 썼다. **그 뒤 ChatKHU로 교차 검토했다** | [02-materials.md](02-materials.md) |

> 셋 다 **생성물이 배포본에 들어가지 않는다.** 들어가는 생성물(문구·아이콘)은 전부 ChatKHU가 만들었다.

### 3. 사람이 결정한 것

01~05의 "사람이 결정·수정한 것"에서 **AI 제안을 버리거나 뒤집은 것**만 모았다.

**① ChatKHU의 권고를 네 군데에서 따르지 않았다** ([02](02-materials.md))
"B 계열이 가장 안전"이라는 권고 대신 **"신호 있을 때" 문구를 뒤집은 것**을 골랐다. 같은 주어를 쓰면 두 문구가 같은 항목임을 바로 알 수 있고 새 주장을 끌어들이지 않는다. 예: `출처 표시`에서 ChatKHU는 "일부 보입니다"를 권했는데, **"일부"가 🟢 자리에서 오히려 부정 신호로 읽힌다.**

**② 아이콘의 "글자 금지"가 지켜지지 않았는데 그대로 받았다** ([02](02-materials.md))
16px에서 `GE`가 뭉개지는 것을 8배 확대로 **실제 확인한 뒤** 판단했다. 방패 형태와 2분할 색으로 식별되고, 16px은 확장 목록에서만 쓰인다. 재생성 반복보다 수용이 낫다고 봤다.

**③ 생성 모델이 지시를 비껴간 것을 고치지 않았다** ([02](02-materials.md))
"약한 낚시성 제목"으로 시킨 3건 중 2건이 강한 낚시성으로 나왔다. **노린 신호는 정답이 아니다.** 라벨은 사람이 글자에 보이는 대로 붙인다.

**④ 가상 기사의 이름이 실존 이름과 겹친 것을 잡아 규칙을 바꿨다** ([02](02-materials.md))
'루미너스'(실존 아이돌), '씽씽'(실제 공유 킥보드), '윤도현'(가수)이 섞여 들어왔다. 앞서 만든 "실존 이름 0건" 검사는 **우리가 정한 주제 이름 자체를 보지 않았다.** 고유명사 규칙을 다시 세우고 쓰기 전에 검색하기로 했다.

**⑤ 측정해 보고 내 판단을 두 번 뒤집었다** ([05](05-test.md))
제목 걷어내기(GE-47)를 넣었다가 **되돌렸다** — 제목에 심은 공격은 판정을 1.00 → 0.97 정도로밖에 움직이지 못했고, 추가한 코드는 실행되지도 않았다. 걷어내기 범위 축소(GE-46)는 72건이 전부 같은 결과라 **유지**했다.

**⑥ Jev에게 묻던 질문 13개를 걷어냈다** ([04](04-build.md), [jev.md 8절](../jev.md))
"이 표현이 글에 있는가"를 Jev가 틀린다는 것을 배포본에 직접 물어 확인하고, 그 질문들을 **코드로 옮겼다.** 문자열 찾기를 분류기에 맡긴 것이 잘못이었다.

**⑦ 모델 셋을 쓰되 판정자는 하나로 묶었다**
처음 설계는 sonar·Jev·프런티어 모델이 각자 판단하는 것이었다. 셋이 다른 말을 하면 일관성이 깨진다고 보고, **sonar는 찾기만, Jev만 판정, 프런티어는 글만** 쓰도록 다시 나눴다.

**⑧ 그 밖**
판단 항목 7개의 선정·가중치·임계값, "하지 않는 것" 네 가지(진위 단정·공유 차단·모르는데 아는 척·언론사 평가), 평가 세트 120건의 구성비(정상 60·경계 30·뚜렷 15·가상 15)와 **정답 라벨은 사람만 붙인다**는 규칙.

### 4. AI가 하지 않은 것

- 점수 합산과 배지 단계 결정 — 코드가 한다 ([jev.md](../jev.md) 3절 ②)
- 사용자에게 보이는 문구의 최종 확정 — **후보를 받아 사람이 고른다**
- 출처 도메인 판단, 날짜 비교 — 코드가 목록·값과 대조한다
- 판단 항목 선정의 최종 결정 — 사람이 한다
- 평가 세트의 정답 라벨 — **사람만 붙인다.** AI가 붙인 정답으로 AI 판단을 재면 숫자가 의미가 없다
- 리포트에 나가는 글의 검열 — 코드가 거른다. 걸리면 고치지 않고 버린다

### 5. 한계

**모델**
- 한국어는 Jev의 주 학습 언어가 아니다 ([jev.md](../jev.md) 4절)
- **"특정 표현이 글에 있는가"를 틀린다.** 글자가 그대로 있어도 0.1~0.2 ([jev.md](../jev.md) 8절). 글의 성질("반복되는가", "고른가")은 맞는다(0.89/0.79)
- 적대적 입력에 흔들릴 수 있다. 본문 공격 72건은 걷어내기로 막았지만, 걷어내기가 못 보는 모양이 있을 수 있다

**측정**
- **정식 평가 세트의 정확도 수치가 아직 없다.** 확인용 표본이 분류당 5건이라 한 건이 20%p를 움직인다. 숫자를 내놓기보다 방향 확인에만 썼다
- 리포트의 기록 대조는 48건 표본에서 자기 인용 17%, 날짜 어긋남 21%를 코드가 걸러 냈다. 표본이 작다

**설계상 하지 않는 것** — 한계이자 의도다
- 진위를 단정하지 않는다 ([product.md](../product.md) 2절)
- 일곱 항목 중 여섯은 **글의 형식**을 본다. 내용이 사실인지 묻지 않는다
- `ai_style_signal`은 신뢰도가 낮다고 알려져 가중치를 0.5로 뒀다

**남은 일**
- 평가 세트 정확도 산출, 오판 피드백 전송, 웹스토어 등록, 개인정보 처리 방침 문서
