# 02. 자료 준비

> 서식4의 **자료 준비** 단계다. 형식과 규칙은 [README.md](README.md)에 있다.
> 항목 하나가 결정 하나다. 최신 항목을 아래에 덧붙인다.

판단과 평가에 쓸 자료를 모으고 고른 과정.

여기 들어갈 것:

- **평가 세트** — 어떤 기사를 몇 건, 어떤 비율로 모았는가 ([../../eval/README.md](../../eval/README.md))
- **라벨링** — 무엇을 보고 🔴이라고 할지 기준을 어떻게 정했는가, 누가 붙였는가
- **출처 도메인 목록** — 어떤 목록을 근거로 삼았는가
- **아이콘·이미지 등 제작 자산**

## 이 단계에서 사람이 쥐고 있어야 할 것

- **라벨이 흔들리면 이후 모든 숫자가 무의미하다.** 라벨링 기준을 AI로 만들었다면 그 사실과 사람이 검토한 내용을 적는다
- **실제 기사 본문을 저장소에 커밋하지 않는다.** URL과 라벨만 둔다
- **테스트용으로 만든 가상 가짜 기사는 `eval/data/private/`에만 둔다.** 그럴듯한 가짜 기사가 공개 저장소에 돌아다니면 그 자체가 문제다
- 외부에서 가져온 자료는 **[sources.md](sources.md)에 출처와 이용 조건을 함께 적는다.** 서식4에 그 표가 있다

## 기록

### 확장 프로그램 아이콘 생성 (GE-9)

- **날짜**: 2026-10-13
- **AI 모델**: **ChatKHU 이미지 생성 에이전트 (GPT Image 2.5 Sunburst)**
- **외부 도구 사용 사유**: 해당 없음 — ChatKHU로 생성했다.
- **주요 프롬프트**: 서비스 성격(기사의 '주의가 필요한 신호'를 알려 주는 확장 프로그램, 진위를 단정하지 않음)을 설명하고 제약을 걸었다. 정사각형·배경 투명, **16×16으로 줄여도 식별 가능할 것**, 글자·숫자 금지, 가는 선·그라데이션·그림자 금지, 밝은 배경과 어두운 배경 양쪽에서 보일 것, 색 2~3가지. 512px 시안 3개 요청. 기존 상표나 서비스 로고를 닮게 만들지 말 것을 함께 명시했다(서식1 4항).
- **결과**: 시안 3종 — ① 문서 + 경고 표시 ② 눈 모양 ③ 방패(초록/네이비 2분할). 셋 다 `GE` 글자가 들어갔다.
- **사람이 결정·수정한 것**:
  - **③ 방패를 선택했다.** 초록/네이비 2분할이 작은 크기에서도 형태가 구분된다.
  - **프롬프트의 "글자 금지"가 지켜지지 않았는데 그대로 수용했다.** 16px에서 `GE`가 뭉개지는 것을 실제로 확인(8배 확대 검증 — [evidence/2026-10-13-icon-16px-zoom.png](evidence/2026-10-13-icon-16px-zoom.png))한 뒤 판단한 것이다. 방패 형태와 2분할 색으로 식별이 되고, 16px은 확장 목록에서만 쓰이며, 일정상 재생성 반복보다 수용이 낫다고 봤다. 다듬는다면 작은 크기용 단순 버전(글자 제거)을 따로 만든다.
  - **받은 PNG에 알파 채널이 없었다.** 투명해 보이던 격자무늬가 실제로는 그림으로 구워져 있었다(3채널, `hasAlpha: false`). 무채색 판정으로 배경을 제거하고 경계를 반투명 처리해 16·32·48·96·128px로 변환했다.
  - 변환 중 **다크 네이비가 반투명해져 색이 날아가는 문제**가 있었다. 네이비 `rgb(24,40,56)`의 색차가 32라 경계 판정 구간에 걸린 탓이다. 어두운 색(`lum ≤ 100`)은 불투명으로 고정해 해결했다.
  - 512px 마스터를 `apps/extension/assets/icon-master.png`에 보관한다. `import` 하지 않아 번들에 포함되지 않는 것을 확인했다.
  - 출처와 이용 조건은 [sources.md](sources.md)에 기재했다. **ChatKHU 생성물의 상업적 이용·2차 가공 조건은 아직 확인하지 못해 TODO로 남아 있다.**
  - (2026-10-16 추가) 아이콘을 만든 모델의 정확한 ID가 `gpt-image-2.5-sunburst`임을 ChatKHU Gateway의 모델 목록에서 확인하고 [sources.md](sources.md)를 고쳤다. 서식4에 모델명을 적어야 하므로 표기가 아니라 ID로 남긴다.

### ChatKHU Gateway로 Jev를 호출할 수 있음을 확인 (GE-29)

- **날짜**: 2026-10-16
- **AI 모델**: `jev-latest` (TypeSafe, ChatKHU Gateway 경유) / 모델 목록 조회는 Gateway API
- **외부 도구 사용 사유**: 해당 없음 — ChatKHU를 통해 호출했다.
- **주요 프롬프트**: Jev 질문 두 개를 실제로 보냈다. `source_citation` — "본문에 주장의 출처(기관명·인물명·문서명)가 구체적으로 적혀 있는가?", `spread_inducement` — "퍼뜨리기를 재촉하는 표현이 있는가?". `state`는 시험용으로 지어낸 한 문장이다(실제 기사 아님).
- **결과**:
  - `POST /v1/gateway/decisions/` → **HTTP 200, 0.86초**, 입력 351 / 출력 42 토큰
  - `state: "전문가에 따르면 이번 조치는 효과가 없을 것이다. 꼭 공유해서 알려주세요!"`
  - `source_citation` → `noul 0.03` / `spread_inducement` → `noul 0.98`
  - 요청·응답 형식이 TypeSafe 공식 API와 같았다. 게이트웨이가 그대로 중계한다.
- **사람이 결정·수정한 것**:
  - **"모델 목록에 있다"에서 멈추지 않고 실제로 호출해 확인했다.** 목록에 이름이 있는 것과 우리 키로 실제로 응답이 오는 것은 다르다.
  - **한국어 판단이 동작하는 것을 이 호출로 처음 확인했다.** 공식 문서는 영어가 주 학습 언어이고 CJK는 똑같이 잘하지 않는다고만 밝히고 있어([../jev.md](../jev.md) 4절), 우리가 직접 재야 하는 값이었다. "전문가에 따르면"을 출처로 보지 않고(0.03) "꼭 공유해서 알려주세요"를 확산 유도로 잡은 것(0.98)은 우리 판단 항목의 의도와 맞는다. 다만 **한 건으로 정확도를 말할 수는 없다.** 측정은 eval에서 한다.
  - **그럼에도 런타임에는 쓰지 않기로 했다.** 게이트웨이 레이트 리밋이 60초에 120건(초당 2건)으로 Jev 직접(초당 80건)의 60분의 1이다. 포털 목록 일괄 검사가 성립하지 않는다. ChatKHU 이용 대상이 교내 재학생이라 사용자 트래픽 대행 가부도 확인되지 않았다. **"되니까 쓴다"가 아니라 쓸 수 있는 범위를 나눴다** — 개발·평가는 이 경로, 런타임은 미정([../jev.md](../jev.md) 6-1절).
  - `state`에 실제 기사 본문을 쓰지 않고 시험용 문장을 지어냈다. 공개 저장소이고 요강의 증빙 원칙이기도 하다.

### 문구 생성 모델 선정 (GE-29)

- **날짜**: 2026-10-16
- **AI 모델**: `claude-sonnet-5-5` (Anthropic, ChatKHU Gateway 경유)
- **외부 도구 사용 사유**: 해당 없음 — ChatKHU를 통해 호출했다.
- **주요 프롬프트**: "기사에서 주장의 출처를 찾지 못한 상황에 쓸 배지 문구 후보 3개. 진위를 단정하지 말 것(가짜/허위/거짓 금지), 20자 이내, 사용자를 가르치려 들지 말 것"
- **결과**: `출처를 찾지 못했어요` / `주장의 출처 확인 안 됨` / `출처 미확인 내용 포함`
- **사람이 결정·수정한 것**:
  - Gateway의 `llm` 모델 60개 중 **`claude-sonnet-5-5`를 골랐다.** 더 싼 모델(`solar-pro4` $0.3/Mtok, `gpt-6-luna` $0.1/Mtok)도 있었지만, 우리가 만들 것은 **배지 문구 몇 줄**이라 총량이 작아 가격 차이가 의미가 없고 품질이 중요하다고 봤다.
  - **별칭이 아니라 버전이 박힌 ID를 쓴다.** 서식4에 어떤 모델로 만들었는지 적어야 한다.
  - 위 세 후보는 **아직 채택하지 않았다.** 모델이 제약(단정 금지·길이·어조)을 지키는지 확인한 것이고, 실제 문구 확정은 GE-16이다.
