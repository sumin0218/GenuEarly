제출 직전에 몰아서 쓰면 기억에 없는 것을 지어내게 된다. **그때그때 남긴다.**

## 서식4가 요구하는 것

요강에 적힌 그대로다.

> 심사위원이 **AI 활용의 깊이와 참가자의 실질적 기여**를 확인할 수 있게 작성
>
> **증빙 원칙**: 전체 대화기록을 무조건 제출하기보다 **핵심 프롬프트 · 버전 변화 · 검증 결과**를
> 선별해 첨부하고, **개인정보 · API 키 · 비공개 정보는 반드시 제거**합니다.

## 기록 형식

각 단계 파일 안에 아래 칸을 채운 항목을 쌓는다. 하나의 결정이 하나의 항목이다.
`AI 모델`과 `주요 프롬프트`는 **서식4 표의 칸 이름 그대로**다.

```markdown
### (제목: 무엇을 하려 했는가)

- **날짜**: YYYY-MM-DD
- **AI 모델**: ChatKHU / Jev 1.13 / 코딩 도구(이름) / 안 씀
- **외부 도구 사용 사유**: ChatKHU가 아닌 도구를 썼다면 왜. ChatKHU만 썼으면 "해당 없음"
- **주요 프롬프트**: 무엇을 물었는가. 길면 요지만. 키·개인정보·기사 본문은 넣지 않는다
- **결과**: AI가 내놓은 것. 길면 요지와 저장 위치
- **사람이 결정·수정한 것**: 무엇을 받아들이고 무엇을 버렸는가. **왜 그랬는가.** 이 칸이 비면 기록이 아니다
```

## 쓸 때 지키는 것

- **잘된 것만 적지 않는다.** AI가 낸 것을 버린 기록이 오히려 설득력이 있다. 왜 버렸는지가 판단 근거다
- **ChatKHU가 대회 필수 도구다.** 다른 도구를 썼다면 사유를 반드시 적는다
- **Jev는 "도구"가 아니라 "제품의 일부"다.** 개발 중 실험은 여기 적고, 런타임 동작 자체는 [../jev.md](../jev.md)와 [../product.md](../product.md)에 적는다
- 프롬프트에 **API 키, 개인정보, 실제 기사 본문 전체**를 넣지 않는다. 요강의 증빙 원칙이기도 하고, 여기는 공개 저장소다
- 캡처를 넣을 때 화면에 키나 개인정보가 찍히지 않았는지 확인한다
- 외부 자료를 썼으면 [sources.md](sources.md)에도 한 줄 추가한다
- PR을 올릴 때 [PR 템플릿](../../.github/PULL_REQUEST_TEMPLATE.md)의 "AI 활용 기록" 칸에 어느 파일에 남겼는지 적는다
