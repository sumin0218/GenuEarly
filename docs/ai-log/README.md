# AI 활용 기록

2026 KHU AI Challenge **서식4 (AI 활용 과정 설명서)**의 증빙이다.
제출 직전에 몰아서 쓰면 기억에 없는 것을 지어내게 된다. **그때그때 남긴다.**

## 왜 남기나

- 서식4는 "AI를 썼다"가 아니라 **"어디에 어떻게 썼고, 사람이 무엇을 결정했는가"**를 묻는다.
- **ChatKHU가 대회 필수 도구다.** 다른 도구를 썼다면 그 사유를 적어야 한다.
- AI가 낸 결과를 그대로 쓴 것과, 보고 고쳐서 쓴 것은 다르다. **고친 부분이 우리 몫이다.**

## 기록 형식

각 단계 파일 안에 아래 다섯 칸을 채운 항목을 쌓는다. 하나의 결정이 하나의 항목이다.

```markdown
### (제목: 무엇을 하려 했는가)

- **날짜**: YYYY-MM-DD
- **도구**: ChatKHU / Jev 1.13 / 코딩 도구(이름) / 안 씀
- **외부 도구 사용 사유**: ChatKHU가 아닌 도구를 썼다면 왜. ChatKHU만 썼으면 "해당 없음"
- **프롬프트 요약**: 무엇을 물었는가. 길면 요지만. 키·개인정보·기사 본문은 넣지 않는다
- **결과**: AI가 내놓은 것. 길면 요지와 저장 위치
- **사람이 결정·수정한 것**: 무엇을 받아들이고 무엇을 버렸는가. **왜 그랬는가.** 이 칸이 비면 기록이 아니다
```

## 쓸 때 지키는 것

- **잘된 것만 적지 않는다.** AI가 낸 것을 버린 기록이 오히려 설득력이 있다. 왜 버렸는지가 판단 근거다.
- **Jev는 "도구"가 아니라 "제품의 일부"다.** 개발 중에 Jev로 실험한 것은 여기 적고, 런타임 동작 자체는 [../jev.md](../jev.md)와 [../product.md](../product.md)에 적는다.
- 프롬프트에 **API 키, 개인정보, 실제 기사 본문 전체**를 넣지 않는다. 여기는 공개 저장소다.
- 캡처를 넣을 때 화면에 키나 개인정보가 찍히지 않았는지 확인한다.
- PR을 올릴 때 [PR 템플릿](../../.github/PULL_REQUEST_TEMPLATE.md)의 "AI 활용 기록" 칸에 어느 파일에 남겼는지 적는다.
