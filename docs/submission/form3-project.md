## 작품 요약 소개 (1,000자)

GenuEarly는 뉴스 기사를 **읽는 순간**에 "주의가 필요한 신호"가 있는지 알려 주는 크롬 확장 프로그램입니다.

사실 확인 서비스는 이미 많습니다. 그러나 대부분 읽고 난 뒤에, 사용자가 따로 찾아가야 쓸 수 있습니다. 그때쯤이면 이미 읽었고 이미 공유한 뒤입니다. 그래서 우리는 시점을 바꿨습니다. 기사를 연 순간과 남에게 넘기려는 순간, 두 곳에 끼어듭니다.

이 제품은 **기사가 참인지 거짓인지 말하지 않습니다.** 대신 글 자체에서 보이는 일곱 가지 신호를 봅니다 — 출처를 밝혔는지, 제목과 본문이 맞는지, 제목이 내용을 감추거나 부풀리는지, 퍼뜨리라고 재촉하는지, 감정을 자극하는지, 기계가 쓴 듯한 문체인지, 근거를 확인하기 어려운 단정이 있는지. 판단은 사용자가 합니다.

기능은 다섯입니다. ① 기사를 열면 오른쪽 아래에 배지가 뜹니다. ② 뉴스 목록에서는 제목 옆에 작은 표시를 달아 낚시성 제목을 알립니다. ③ 아무 페이지에서나 글을 드래그해 오른쪽 클릭으로 검사할 수 있습니다. ④ 주의 신호가 뚜렷한 기사를 공유하려 하면 알림을 띄웁니다 — 막지는 않습니다. ⑤ 기사 주변의 공개 기록을 모아 리포트를 만듭니다.

AI는 역할을 나눠 씁니다. **ChatKHU**는 사용자가 읽는 모든 문구와 아이콘을 만들었습니다 — 생성물이 배포본에 그대로 들어갑니다. **Jev**는 실행 중에 기사를 판단합니다. 점수 합산과 배지 단계 결정, 출처 도메인 대조는 **코드**가 합니다. 모델이 잘하는 일과 코드가 정확한 일을 갈라 둔 것입니다.

확신이 부족하면 "판단하지 못함"이라고 말합니다. 그것은 오류가 아니라 결과의 한 종류입니다.

> 글자 수: 공백 포함 약 870자

## 1. 문제 인식과 주제 적합성 (1,000자)

**문제.** 잘못된 정보는 읽은 뒤가 아니라 **읽는 중**과 **남에게 넘기는 순간**에 퍼집니다. 기존 팩트체크는 사후 대응입니다. 이미 읽은 사람에게는 늦고, 찾아가지 않는 사람에게는 닿지 않습니다.

**왜 이 주제인가.** 포털 뉴스는 제목만 보고 넘어가는 소비가 많습니다. 제목이 내용을 감추거나 부풀려도 본문을 열기 전에는 알 수 없고, 열어 본 뒤에도 출처가 "전문가에 따르면"뿐인지 일일이 확인하지 않습니다. 이 확인은 사람이 하기에는 번거롭고 기계가 돕기에는 적당한 일입니다.

**목적.** 판단을 대신하는 것이 아니라 **판단할 재료를 제때 보여 주는 것**입니다. 그래서 우리는 진위를 선언하지 않기로 했습니다. "이 기사는 가짜입니다"라고 말하는 순간 사용자는 확인을 멈추고 우리를 믿거나 무시합니다. 둘 다 원하는 바가 아닙니다.

**기대 효과.** 읽기를 멈추게 하는 것이 아니라 **한 번 더 보게** 하는 것입니다. 출처가 비어 있다는 사실, 제목이 본문보다 세다는 사실, 같은 사안을 다른 매체가 다르게 적었다는 사실을 그 자리에서 보여 주면, 공유 버튼을 누르기 전에 잠깐 멈출 여지가 생깁니다.

**대회 주제와의 적합성.** AI가 사람을 대신해 결론을 내리는 것이 아니라, **AI가 할 수 있는 일과 할 수 없는 일을 갈라 설계한 것**이 이 작품의 핵심입니다. 판단 모델은 글의 성질을 재고, 문구 생성 모델은 사람이 읽을 말을 만들고, 숫자를 다루는 일은 코드가 합니다. 이 분담은 모델의 한계를 실제로 측정해서 정한 것입니다(아래 3·4항).

> 글자 수: 공백 포함 약 820자

## 2. 핵심 아이디어와 사용자 경험 (제한 없음 · 이미지·도표 삽입)

### 한 줄

**읽는 순간에, 글 자체에서 보이는 신호만, 단정하지 않고 보여 준다.**

### 쓰는 순서

```
① 뉴스 목록을 연다
   └ 제목 옆에 작은 표시가 붙는다. 제목만 보고 낸 결과다
      (오른쪽 아래 "제목 표현 안내" 상자가 표시의 뜻을 설명한다)

② 기사를 연다
   └ 몇 초 뒤 오른쪽 위에 "살펴보기를 마쳤습니다" 말풍선
   └ 오른쪽 아래에 배지 — 🟢 / 🟡 / 🔴 / ⚪

③ 확장 아이콘을 누른다
   └ 일곱 항목 중 어떤 것이 걸렸는지, 본문의 어느 대목인지

④ "주변 기록 모아 보기"
   └ 같은 사안을 다른 매체가 어떻게 적었는지 모아 새 탭에 리포트

⑤ 기사를 복사·공유하려 한다
   └ 🔴 였다면 알림. 막지는 않는다
```

> **삽입할 이미지** (제출 시 캡처)
> 1. 목록 화면 — 제목 옆 표시 + 범례 상자
> 2. 기사 화면 — 배지와 말풍선
> 3. 팝업 — 일곱 항목과 걸린 대목
> 4. 리포트 화면 — 문장별로 찾은 주변 기록

### 다섯 기능

| | 기능 | 보는 것 | 특징 |
| --- | --- | --- | --- |
| ① | 기사 자동 검사 | 제목 + 본문 | 배지 4단계. **점수(숫자)는 보여 주지 않는다** — 정밀해 보이는 숫자는 단정으로 읽힌다 |
| ② | 목록 표시 | **제목만** | 낚시성 제목만 본다. 근거가 제목뿐이라 표시도 배지보다 약하게 그린다 |
| ③ | 선택 글 검사 | 드래그한 글 | 뉴스 사이트가 아닌 곳(메신저·SNS·커뮤니티)에서도 쓴다 |
| ④ | 공유 직전 알림 | — | **막지 않는다.** 닫으면 그만이다 |
| ⑤ | 공개 기록 리포트 | 기사 + 외부 검색 | 기사 하나가 전하지 못하는 주변 보도를 모은다 |

### 판단 항목 일곱

| 항목 | 보는 것 |
| --- | --- |
| 출처 표시 | 기관명·실명이 있는지, "전문가에 따르면"처럼 이름이 빠졌는지 |
| 제목과 본문 | 제목의 핵심이 본문에 있는지, 조건이 빠졌는지 |
| 제목 표현 | 내용을 감추거나("그 이유는") 부풀리는지("충격") |
| 공유 유도 | 퍼뜨리라고 재촉하는지 |
| 감정적 표현 | 분노·공포를 자극하는 표현의 정도 |
| 글의 문체 | 기계 생성 글에서 흔한 문체 특징 |
| 확인하기 어려운 주장 | 확정 서술인데 문장 안에 근거가 없는 경우 |

**일곱 중 여섯은 글의 형식을 봅니다.** 내용이 사실인지 묻지 않습니다. 그래서 정치적 입장이나 매체에 따라 결과가 달라지지 않습니다.

### 리포트의 파이프라인 — 모델 셋, 판정자는 하나

```
sonar-pro   주변 기록을 찾는다      (참·거짓을 선언하지 않는다)
    ↓
Jev         기사 문장과 맞춰 본다    (유일한 판정자. 바깥 지식을 쓰지 않는다)
    ↓
코드        거른다                  (자기 인용·지어낸 주소·날짜 어긋남)
    ↓
Claude      읽을 수 있는 글로 엮는다 (판정하지 않는다)
```

모델을 여러 개 쓰면서도 **판정은 Jev 하나**에게만 맡겼습니다. 셋이 각자 판단하면 서로 다른 말을 하게 되고, 사용자는 어느 쪽도 믿지 못합니다.

## 3. 창의성·차별성 (500자)

**차별점은 "하지 않기로 한 것"에 있습니다.**

진위를 단정하지 않습니다. 가짜뉴스 판별기는 틀렸을 때 되돌릴 방법이 없고, 맞았을 때도 사용자의 확인을 멈추게 합니다. 우리는 신호만 보여 주고 판단을 넘깁니다. "가짜·허위·거짓" 같은 단어를 사용자 문구에서 **금지어로 지정하고 테스트로 막았습니다.**

모르면 모른다고 합니다. 확신이 낮으면 ⚪ "판단하지 못함"을 띄웁니다. 오류 표시가 아니라 결과의 한 종류입니다.

공유를 막지 않습니다. 알림만 띄우고 버튼을 가리지 않습니다.

언론사를 평가하지 않습니다. 매체 이름이 아니라 개별 기사의 글만 봅니다.

**사람의 기획이 들어간 자리**는 이 네 가지 금지, 일곱 항목의 선정과 가중치, 그리고 **모델의 한계를 측정해 역할을 다시 나눈 일**입니다. Jev가 "이 표현이 글에 있는가"를 틀린다는 것을 실측하고(3·4항), 그 질문 13개를 걷어내 코드로 옮겼습니다. 생성물을 그대로 쓴 것이 아니라 재어 보고 버린 것입니다.

> 글자 수: 공백 포함 약 490자

## 4. 실용성·완성도·확장성 (1,000자)

**현재 구현 수준.** 다섯 기능 모두 동작합니다. 네이버(일반·스포츠·연예), 다음, 인사이트, 위키트리의 기사와 목록을 지원합니다. 자동 검사 테스트 739건(확장 470·중계 127·공용 142)이 통과하며, 판단 기준·문구·보안 규칙은 각각 테스트로 고정돼 있습니다.

**작동 범위와 한계.** 한국어는 Jev의 주 학습 언어가 아닙니다. 실측에서 **"특정 표현이 글에 있는가"를 묻는 질문은 글자가 그대로 있어도 틀렸습니다**(0.1~0.2). 반대로 "비슷한 문장 구조가 반복되는가" 같은 **글의 성질**은 맞았습니다(0.89/0.79). 이 차이를 확인하고 설명용 하위 질문 22개 중 13개를 걷어냈습니다.

적대적 입력도 재 봤습니다. 기사 본문에 판단기를 노리는 문장을 심어 72건을 돌렸고, 걷어내기 범위를 줄인 뒤에도 **결과가 전부 동일**했습니다. 제목에 심은 공격은 판정을 1.00 → 0.97 정도로밖에 움직이지 못해, 넣었던 제목 걷어내기 코드를 **되돌렸습니다**.

정식 평가 세트(라벨 36~37건)의 정확도 수치는 아직 산출 전입니다. 확인용 표본이 분류당 5건이라 한 건이 20%p를 움직여, 숫자를 내놓기보다 방향 확인에만 쓰고 있습니다.

**개인정보.** 브라우저에 남는 것은 셋뿐이고 각각 수명이 있습니다. 판단 캐시는 URL의 SHA-256과 점수만(6시간), 보고 있는 리포트는 브라우저를 닫으면 사라지고, 보관함만 제목·주소를 남깁니다(30일·20건·사용자가 삭제). API 키는 중계 서버 환경변수에만 둡니다.

**확장성.** 지원 사이트는 match pattern 한 줄로 늘어납니다. 판단 항목은 JSON 스키마에 정의돼 있어 코드 수정 없이 더하거나 뺄 수 있습니다. 다음 단계는 웹스토어 등록, 오판 피드백 전송, 평가 세트 확대입니다.

> 글자 수: 공백 포함 약 960자
