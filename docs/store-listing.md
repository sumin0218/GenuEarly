## 2. 스토어 등록정보

### 이름

```
GenuEarly
```

### 요약 (132자 이내)

```
기사를 읽는 순간에 출처·제목·표현을 살펴 확인해 볼 점을 짚어 줍니다. 진위는 단정하지 않습니다.
```

### 설명

```
뉴스를 다 읽고 나서 의심하면 늦습니다. GenuEarly는 기사를 연 그 순간에
확인해 볼 점이 있는지 알려 줍니다.

■ 무엇을 하나

· 기사를 열면 오른쪽 아래에 배지가 뜹니다 (0.5~1.5초)
  눈에 띄는 신호 없음 / 확인해 볼 점 있음 / 주의할 신호 있음 / 판단하지 못함
· 걸린 대목은 본문에 형광펜으로 칠합니다. 올려놓으면 왜 걸렸는지 뜹니다
· 뉴스 목록에서는 제목 옆에 표시가 붙습니다
· 리포트를 누르면 같은 사안의 주변 보도를 모아 견주어 보여 줍니다

■ 무엇을 보나

기사의 글만 봅니다. 일곱 가지입니다.

· 출처 표시 — 출처가 이름으로 적혀 있는가
· 제목 표현 — 제목이 내용을 감추거나 부풀리는가
· 제목과 본문 — 둘이 어긋나는가
· 공유 유도 — 퍼뜨리라고 재촉하는가
· 감정적 표현 — 분노·공포를 끌어올리는 말을 쓰는가
· 글의 문체 — 기계로 쓴 듯한 특징이 있는가
· 확인하기 어려운 주장 — 근거 없이 단정하는가

■ 하지 않는 것

진위를 단정하지 않습니다. "이 기사는 거짓" 이라고 말하지 않습니다.
글에서 걸리는 신호를 보여 드릴 뿐이고, 판단은 읽는 사람이 합니다.
신호가 없다는 것이 사실이라는 뜻도 아닙니다. 잘 쓰인 거짓 기사는
신호가 없어서 걸리지 않습니다.

언론사를 평가하지 않습니다. 기사 하나의 글만 봅니다.

■ 개인정보

· 계정을 만들지 않습니다. 광고도 분석 도구도 추적도 없습니다
· 받는 권한은 storage 와 contextMenus 둘뿐입니다
```

## 3. 스크린샷 — **아직 만들지 않았다**

**1280×800 또는 640×400.** 최소 1장, 최대 5장. 여백이 있어도 되지만 **크기는 정확히 맞아야 한다.**

가지고 있는 사진은 `landing/assets/shots/` 에 있지만 **크기가 맞지 않는다.** 캔버스를
1280×800 으로 두고 그 안에 넣어야 한다.

| # | 무엇 | 쓸 것 |
| --- | --- | --- |
| 1 | 기사 화면 — 배지와 본문 형광펜 | `hero-article.png` |
| 2 | 형광펜과 올려놓았을 때 뜨는 사유 | `feature-highlight.png` |
| 3 | 뉴스 목록 — 제목 옆 표시 | `feature-portal.png` |
| 4 | 리포트 | `feature-report.png` |

**실제 기사로 찍지 않는다.** [testJournal](../eval/fixtures/sample-article/) 을 쓴다
— 이유는 [landing/README.md](../landing/README.md) 에 적어 두었다.

선택 항목(없어도 제출된다): 작은 프로모 타일 440×280, 마키 1400×560.

## 4. 개인정보 보호 탭

### 단일 목적 (Single purpose)

```
뉴스 기사를 읽을 때, 그 기사의 글에서 확인해 볼 만한 신호를 찾아 보여 주는 것
하나입니다. 다른 기능을 겸하지 않습니다.
```

### 권한 사유

| 권한 | 붙여 넣을 글 |
| --- | --- |
| `storage` | 판단 결과를 짧게 캐시하고(같은 기사를 다시 열 때 중복 요청을 막기 위해), 사용자가 직접 만든 리포트를 보관함에 두기 위해 필요합니다. 캐시에는 기사 글을 넣지 않고 주소의 해시와 점수만 둡니다. |
| `contextMenus` | 사용자가 드래그한 글을 오른쪽 클릭 메뉴에서 바로 검사할 수 있게 하기 위해 필요합니다. |
| 호스트 접근 | 지원하는 뉴스 사이트(네이버·다음·인사이트·위키트리)의 기사와 목록 페이지에서 제목과 본문을 읽어 판단하고, 배지와 형광펜을 그 페이지에 그리기 위해 필요합니다. 와일드카드를 쓰지 않고 주소를 하나하나 적었으며, 네이버 댓글 페이지는 제외했습니다. |
| 원격 코드 | **사용하지 않습니다.** 패키지에 담긴 코드만 실행합니다. `eval`, `new Function`, 외부 스크립트 로드가 없습니다. |

### 데이터 사용 — 체크할 것

수집한다고 **표시해야 하는 것 하나**뿐이다.

| 항목 | |
| --- | --- |
| **웹사이트 콘텐츠** | ☑ 기사 제목과 본문을 판단을 위해 중계 서버로 보낸다 |
| 개인 식별 정보 | ☐ |
| 건강 정보 | ☐ |
| 금융·결제 정보 | ☐ |
| 인증 정보 | ☐ |
| 개인 통신 내용 | ☐ |
| 위치 | ☐ |
| 사용자 활동 | ☐ (분석 도구 없음) |

### 서약 세 줄 — 전부 **예**

- 승인된 용도로만 쓰며, 그 외 용도로 넘기거나 팔지 않습니다
- 제3자에게 판매하지 않습니다
- 신용도 판단이나 대출 목적으로 쓰지 않습니다

> **"웹사이트 콘텐츠" 를 반드시 체크한다.** 기사 본문이 실제로 서버로 나간다.
> 체크하지 않으면 허위 신고이고, 적발되면 등록이 내려간다.

## 5. 올린 뒤

1. **심사는 보통 며칠**이다. 권한이 적고 원격 코드가 없어 빠른 편이다
2. 통과하면 **비공개 링크**가 나온다. 그 링크를 아는 사람만 설치할 수 있다
3. 랜딩의 설치 절([landing/index.html](../landing/index.html) `#install`)을
   **"zip 내려받아 개발자 모드" 에서 "스토어에서 설치" 로 바꾼다.** 지금 글은
   스토어 전의 것이다
4. [`landing/privacy.html`](../landing/privacy.html) 의 "마지막 고침" 날짜를 맞춘다

### 공개로 바꾸기 전에

**사용자별 한도가 먼저다.** 지금 중계에는 IP당 분당 한도와 전체 분당 한도만 있고
**사용자별 일일 한도가 없다.** 공개 상태에서 설치가 늘면 크레딧이 먼저 바닥난다.

- [ ] 사용자별 일일 한도
- [ ] 크레딧이 바닥났을 때 사용자에게 보여 줄 문구 (지금은 그냥 실패한다)
- [ ] 대회 크레딧이 아닌 자체 예산
