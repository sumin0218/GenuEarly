# 기술 스택

**무엇을 쓰고, 왜 그것을 골랐고, 무엇을 안 쓰기로 했는가.**

- *어떤 조각이 무엇을 맡는가*는 [architecture.md](architecture.md)
- 이 문서는 **도구 선택의 기록**이다. "왜 이걸 썼지"라는 질문의 답이 여기 있다

> 확정일이 적힌 것은 결정된 날짜다. 바꾸려면 그 근거가 아직 유효한지 먼저 본다.

---

## 1. 전체

| | |
| --- | --- |
| 구조 | **npm 워크스페이스 모노레포** (`apps/*`, `packages/*`) |
| 언어 | **TypeScript** — 모든 앱 |
| Node | 22 (CI 기준) |
| 포매터·린터 | **없다.** [.editorconfig](../.editorconfig)만 적용 |

루트 [package.json](../package.json)은 **커밋 검사 도구와 워크스페이스 연결 전용**이다.
여기에 앱 의존성을 넣지 않는다.

**포매터를 안 넣은 이유**: 지금 넣으면 기존 파일 전체가 바뀌어 리뷰 diff 가 커진다.
제출 후에 넣는다. `.editorconfig` 가 인코딩·줄바꿈·들여쓰기는 잡고 있다.

## 2. 확장 프로그램 — `apps/extension`

**확정 2026-10-14** ([apps/extension/AGENT.md](../apps/extension/AGENT.md))

| | |
| --- | --- |
| 프레임워크 | **WXT 0.21** — MV3 전용, Vite 기반 |
| 빌드 | Vite 8 |
| 테스트 | Vitest 5 |
| UI | **없음.** 바닐라 DOM + Shadow DOM |
| 패키징 | `wxt zip` |

### 왜 WXT 인가

둘이 내장이라서다. **직접 만들었어야 할 것들이다.**

- **`createShadowRootUi`** — Shadow DOM 주입. 우리 규칙이 요구하는 것인데, 직접 만들면 스타일 격리·재부착·정리를 전부 손으로 해야 한다
- **`wxt zip`** — 제출용 패키징

CRXJS 도 활발하다(v3.0.0, 2026-09). `manifest.json` 을 직접 관리해 권한 표와 1:1로 대응되는 장점이 있지만,
위 둘을 직접 구현해야 한다.

> WXT 공식 비교 문서가 CRXJS 를 "maintenance mode"라고 적고 있는데 **npm 배포 이력과 맞지 않는다.**
> 경쟁 도구에 대한 서술을 그 도구 제작자의 문서로 판단하지 않는다.

### 왜 UI 라이브러리를 안 쓰나

만드는 것이 **배지와 작은 오버레이**다. SPA 가 아니다. React 를 얹을 크기가 아니다.

### TypeScript 지만 타입을 강제하지 않는다

WXT 템플릿이 전부 TypeScript 다. `.js` 로 내리면 공식 문서 예제를 그대로 쓸 수 없어 오히려 학습 비용이 커진다.
`.ts` 를 쓰되 **타입 오류가 빌드를 막지 않는다.** 평범한 JS 를 써도 된다.

## 3. 중계 서버 — `apps/proxy`

**확정 2026-10-20** ([apps/proxy/AGENT.md](../apps/proxy/AGENT.md))

| | |
| --- | --- |
| 런타임·배포 | **Cloudflare Workers** |
| 프레임워크 | **없음.** `fetch` 핸들러 하나 |
| 테스트 | Vitest 5 |
| CLI | wrangler 4 |
| 설정 | `wrangler.jsonc` |
| 키 | `wrangler secret` / 로컬은 `.dev.vars` |

### 왜 Cloudflare Workers 인가

**콜드 스타트 때문이다.** 배지가 늦게 뜨면 기능 ①이 사실상 없는 기능이 된다.

| | 콜드 스타트 |
| --- | --- |
| **Cloudflare Workers** | **10ms 미만** |
| Vercel Hobby | 200~800ms. Hobby 는 비상업 전용 |
| Render 무료 | **30~60초** (15분 유휴 후 잠듦) |

Render 는 심사위원이 확장을 켰을 때 1분을 기다리게 만든다. 전시장에서도 같다.

**CPU 10ms 제한은 우리에게 안 걸린다.** Cloudflare 문서가 *"네트워크 요청을 기다리는 시간은 CPU 시간에
들어가지 않는다"* 고 명시한다. 우리가 쓰는 CPU 는 JSON 검증과 요청 조립뿐이다.

무료 한도는 하루 10만 요청, 요청당 서브요청 50개다.

### 왜 프레임워크를 안 쓰나

엔드포인트가 둘(`/health`, `/v1/judge`)이다. 라우터를 얹을 만큼 크지 않다.

## 4. 공유 패키지

| | 상태 | 스택 |
| --- | --- | --- |
| [`packages/shared`](../packages/shared/) | JSON 있음, 코드 없음 | **`judgment-items.json` — 언어 중립.** 점수 합산은 TS (GE-15) |
| [`packages/content`](../packages/content/) | 비어 있음 | 문구를 **JSON** 으로 (GE-16) |
| [`eval`](../eval/) | 비어 있음 | Node/TS 스크립트 (GE-13) |
| [`tools/content-gen`](../tools/content-gen/) | 설정만 | Node/TS (GE-16) |

### `judgment-items.json` 을 JSON 으로 둔 것이 설계를 바꿨다

스택이 정해지지 않았을 때 **언어에 묶이지 않게** 두려고 한 선택이었는데, 결과적으로 두 가지가 따라왔다.

- 중계 서버가 **어떤 언어든** 될 수 있었다 (결국 TS 로 갔지만 강제가 아니었다)
- 서버는 이 파일을 읽어 **검증만** 하고, **점수 합산을 확장으로 보낼 수 있었다**

**문구도 같은 이유로 JSON 이다.** 개발자가 아닌 사람이 읽고 고칠 수 있어야 하고,
ChatKHU 가 생성한 **데이터**지 코드가 아니다.

### 빈 패키지를 미리 만들지 않는다

`packages/content` 와 `eval` 에 `package.json` 조차 없다. **그 작업 PR 에서 만든다.**
쓰지도 않을 뼈대를 미리 두면 관리할 것만 는다.

## 5. AI

**확정 2026-10-16** ([jev.md](jev.md) 6-1절, [ai-log/sources.md](ai-log/sources.md))

| 주체 | 모델 ID | 경로 | 역할 |
| --- | --- | --- | --- |
| **ChatKHU** | `claude-sonnet-5-5` | Gateway | 사용자 노출 문구 **생성** |
| **ChatKHU** | `gpt-image-2.5-sunburst` | Gateway | 확장 아이콘 **생성** |
| **Jev** | `jev-1.13.0` 으로 보냄 (응답은 `jev-latest`) | **ChatKHU Gateway 경유** | 런타임 판단 |
| 코드 | — | — | 점수 합산, 배지 단계, 출처 도메인 |

**ChatKHU 생성물은 배포본에 그대로 들어간다.** 개발 도구가 아니라 **결과물의 구성 요소**다.
사용자가 읽는 모든 문구와 아이콘이 ChatKHU 생성물이고, **Jev 는 사용자에게 보이는 글을 한 글자도 쓰지 않는다.**

### 왜 Jev 를 게이트웨이로 부르나

**키가 하나로 끝난다.** TypeSafe 계정 발급·약관·결제가 필요 없다. 요금도 같다($0.042/Mtok).

**2026-10-21 에 확정했다 (GE-11).** 미해결이던 둘을 확인했다.

- **이용 조건** — **대회 결과물 단계에서는 개인 키로 사용자 트래픽을 대행해도 된다.**
  보낸 내용은 보관하지 않고, 키는 심사·전시 기간 안에 만료되지 않는다 ([jev.md](jev.md) 6-1절)
- **레이트 리밋 분당 120건** — **고정이다. 올릴 수 없다.** 다만 속도 제한이 아니라 분 단위 예산이라
  지연은 문제가 아니다 (기사 하나 0.66초). 남는 것은 처리량 천장이고,
  **정확도를 지키려고 그 천장을 받아들였다** ([requirements.md](requirements.md) 8-1절)

> **TypeSafe 직접 계약은 v1.0.0 에서 쓰지 않는다. 다만 아래 7절 "안 쓰기로 한 것"에는 넣지 않았다.**
> 이용 조건이 **대회 결과물 단계까지**라서, 대회 이후 일반 배포를 결정하면 다시 확인해야 하고
> 그때 이 선택이 다시 열린다.

### 모델 버전 — 보낼 수는 있지만 확인할 수 없다

보내는 쪽은 `jev-1.13.0` 으로 고정한다. 게이트웨이가 받는 것은 2026-10-21 에 확인했다.

**다만 응답의 `model` 은 항상 `jev-latest` 로 돌아온다.** 게이트웨이가 별칭으로 정규화한다.
어느 버전이 실제로 답했는지는 이 경로에서 확인할 수 없다 ([jev.md](jev.md) 6-1절).

## 6. 저장소 도구

| | |
| --- | --- |
| 커밋 메시지 검사 | commitlint 20 + husky 9 |
| CI | GitHub Actions — `pr-title` `branch-name` `pr-source` `extension` `proxy` |
| 시크릿 스캔 | GitGuardian |
| 이슈 관리 | Jira (`GE`) + Atlassian CLI (`acli`) |

**규칙은 테스트로 지킨다.** 커밋 규칙·브랜치 규칙·manifest 권한 모두 검사 스크립트가 있고,
그 검사가 실제로 거르는지 확인하는 테스트도 함께 둔다. 켜 놓고 확인하지 않은 규칙은 조용히 죽는다.

## 7. 안 쓰기로 한 것

고를 때마다 "왜 저건 안 썼냐"는 질문이 따라온다. 답을 여기 남긴다.

| 무엇 | 왜 |
| --- | --- |
| **Plasmo** | npm 최종 배포 2025-05. 17개월 정체 |
| **CRXJS** | 활발하지만 Shadow DOM 주입과 zip 패키징을 직접 만들어야 한다 |
| **Render 무료** | 콜드 스타트 30~60초. 심사·전시에서 치명적 |
| **Vercel Hobby** | 비상업 전용이라 애매하고, 콜드 스타트도 Workers 보다 느리다 |
| **web-ext** | 파이어폭스를 지원하지 않는데 취약점 있는 의존성을 끌고 온다 (제거 후 9건 → 0건) |
| **reicon** (아이콘 라이브러리) | `svg.innerHTML` 을 쓴다. 우리 규칙과 부딪힌다. 필요하면 MIT 라 경로만 가져온다 |
| **UI 프레임워크 · 라우터** | 만드는 규모가 작다 |
| **런타임 생성 모델** | 환각·프롬프트 인젝션·지연. 문구는 미리 만들어 둔다 ([jev.md](jev.md) 3절 ⑨) |

## 8. 의존성을 추가할 때

- 이름·다운로드 수·**최근 배포일**을 확인한다. AI 가 제안한 패키지는 실제로 존재하는지 본다
- 확장 프로그램 번들에 들어가는 것은 특히 적게 가져간다. 사용자 브라우저에서 우리 권한으로 돈다
- 추가 후 `npm audit` 를 본다. **취약점이 나오면 뿌리를 추적한다.** 무시 처리하지 않는다
- 라이선스를 [ai-log/sources.md](ai-log/sources.md)에 적는다. 서식1 3항이 요구한다
