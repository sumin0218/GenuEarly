# packages/content

**사용자에게 보이는 문구를 모아 두는 곳이다.** 배지 설명, 공유 알림, 피드백 안내, 오류 안내 전부.

**문구는 JSON 으로 둔다.** 코드가 아니라 데이터다 (GE-16).

## 왜 따로 두는가

- 문구가 코드 곳곳에 흩어지면 **한 군데만 단정적으로 쓰여 있어도** 제품의 전제가 무너진다. 한곳에 모아 두면 전부 한 번에 검토할 수 있다
- **문구는 ChatKHU로 작성한다.** Jev가 만들지 않는다 — 글을 생성하도록 학습된 모델이 아니다 ([../../docs/jev.md](../../docs/jev.md) 3절 ⑨)
- 코드는 판단 결과에 맞는 문구를 **고를** 뿐이다

## 문구 규칙

원본은 [../../docs/product.md](../../docs/product.md) 2·6절이다.

- **단정하지 않는다.** "가짜 뉴스", "허위", "거짓"을 쓰지 않는다. "~일 수 있습니다", "확인해 보세요"로 쓴다
- **가르치려 들지 않는다.** 사용자가 판단한다
- **⚪의 문구는 사과가 아니라 설명이다.** "판단하지 않았습니다"이지 "실패했습니다"가 아니다
- **점수를 숫자로 보여 주지 않는다.** 정밀해 보이는 숫자는 단정으로 읽힌다
- **④ 공유 알림은 알림이다.** 막는 말투를 쓰지 않는다
- 짧게 쓴다. 배지 옆에서 읽히는 글이다

## 여기 들어갈 것

| 문구 | 쓰는 곳 |
| --- | --- |
| 배지 4단계의 이름과 설명 | ① ② ③ |
| 판단 항목별 "걸린 이유" 설명 | ① 배지 상세 |
| 공유 직전 알림 | ④ |
| 피드백 동의 안내 — **무엇을 보내는지** | ⑤ |
| ⚪ 판단 보류 안내 | 전부 |

## 고칠 때

- 문구를 바꾸면 **AI 활용 기록을 남긴다** ([../../docs/ai-log/](../../docs/ai-log/)). 사용자 노출 문구는 ChatKHU의 주 역할이라 서식4의 증빙이 된다
- 문구 변경은 `design` 또는 `docs`가 아니라 내용이 바뀌면 `feat`/`fix`다. 보이는 글이 제품의 일부다
