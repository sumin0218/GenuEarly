## 붙여 넣을 블록

````text
당신은 한국어 UI 문구를 쓰는 사람입니다. 크롬 확장 프로그램 "GenuEarly" 에 들어갈 문구를 써 주세요.

# 이 제품이 하는 일

뉴스 기사를 읽는 순간에, 그 기사에 "주의가 필요한 신호" 가 있는지 알려 줍니다.
AI 가 기사의 출처 표기·제목과 본문의 일치·감정적 표현 같은 것을 보고 신호를 찾습니다.

# 가장 중요한 전제 (어기면 제품이 무너집니다)

이 제품은 기사가 참인지 거짓인지 **말하지 않습니다.** 신호만 보여 주고 판단은 사용자가 합니다.

- "가짜 뉴스", "허위", "거짓", "사실이 아닙니다" 같은 단정하는 말을 쓰지 마세요
- "~일 수 있습니다", "확인해 보세요" 처럼 여지를 두세요
- 사용자를 가르치려 들지 마세요. 훈계하는 말투를 쓰지 마세요
- 점수나 확률을 숫자로 말하지 마세요. 정밀해 보이는 숫자는 단정으로 읽힙니다
- 판단하지 못한 경우는 **사과가 아니라 설명**입니다.
  "판단하지 않았습니다" 는 되고 "죄송합니다", "실패했습니다" 는 안 됩니다
- 짧게 쓰세요. 기사 위에 떠 있는 작은 상자 안에서 읽히는 글입니다

# 써야 할 문구

## 1. 배지 5단계 — 이름과 설명

기사 오른쪽 아래에 뜨는 작은 상자입니다. 이름은 한 줄에 들어가야 합니다.

| 상태 | 언제 | 지금 임시로 쓰는 말 |
| --- | --- | --- |
| PENDING | 판단을 기다리는 중 | 살펴보는 중 |
| SAFE | 눈에 띄는 신호가 없음 | 눈에 띄는 신호 없음 |
| CHECK | 신호가 조금 있음 | 확인해 볼 점이 있음 |
| CAUTION | 신호가 뚜렷함 | 주의가 필요한 신호 |
| UNDETERMINED | 판단하지 못함 | 판단하지 못함 |

- 이름: 각 10자 이내
- 설명: 각 한 문장, 40자 이내
- SAFE 가 "이 기사는 믿을 만합니다" 로 읽히면 안 됩니다. **신호를 못 찾았을 뿐**입니다
- 다섯이 서로 뚜렷이 구분돼야 합니다

## 2. 판단 항목 7개 — 사용자용 이름과 "걸린 이유" 설명

배지를 누르면 어떤 항목이 걸렸는지 보여 줍니다. **지금은 영어 코드 이름이 그대로 보입니다.**

각 항목마다 세 가지를 써 주세요.
  (가) 사용자용 이름 — 12자 이내
  (나) 신호가 있을 때 보여 줄 한 줄 — 35자 이내
  (다) 판단하지 못했을 때 보여 줄 한 줄 — 35자 이내

| 코드 이름 | 무엇을 보는가 |
| --- | --- |
| source_citation | 본문이 주장의 출처를 밝히는 방식. 기관명·실명이 있는지, "전문가에 따르면" 처럼 이름이 빠졌는지, 아예 없는지 |
| headline_body_match | 제목이 전하는 내용이 본문과 맞는지. 어긋나는지, 일부만 반영했는지 |
| clickbait_headline | 제목이 내용을 감추거나("그 이유는") 부풀리는지("충격", "역대급") |
| spread_inducement | 글이 퍼뜨리라고 재촉하는지. "꼭 공유하세요" 같은 표현 |
| emotional_language | 분노·공포·혐오를 자극하는 표현을 얼마나 강하게 쓰는지 |
| ai_style_signal | 기계가 생성한 글에서 흔한 문체 특징이 보이는지. **글의 진위와는 별개입니다** |
| unverifiable_claim | 근거를 밝히지 않고 단정한 문장이 얼마나 있는지 |

- ai_style_signal 은 특히 조심해 주세요. "AI 가 썼다" 고 단정하면 안 됩니다
- "출처가 없습니다" 보다 "출처를 찾지 못했습니다" 쪽이 맞습니다. 우리가 못 본 것일 수 있습니다

## 3. 판단하지 못했을 때 (⚪)

왜 판단하지 못했는지 사용자에게 구분해서 알려 주지 않습니다. 이유가 무엇이든 한 가지 문구입니다.

- 제목 한 줄 (15자 이내) 과 설명 한 줄 (50자 이내)
- **사과가 아니라 설명입니다.** 오류 메시지처럼 보이면 안 됩니다
- "모르겠다" 를 솔직하게 말하는 것이 이 제품의 미덕이라는 느낌이면 좋겠습니다

## 4. 공유 직전 알림

주의 신호가 뚜렷한(CAUTION) 기사를 공유하거나 주소를 복사하려 할 때 뜹니다.

- 한 문장, 45자 이내. 닫기 버튼의 글자도 함께
- **공유를 막지 않습니다.** 막는 말투, 겁주는 말투를 쓰지 마세요
- "정말 공유하시겠습니까?" 같은 되묻는 말투도 피해 주세요. 알리기만 합니다

## 5. 피드백 동의 안내

판단이 틀렸다고 사용자가 알려 줄 수 있습니다. 보내기 전에 **무엇을 보내는지** 알려야 합니다.

보내는 것: 기사 주소, 화면에 떴던 판단 결과, 사용자가 맞다고 본 판단, 확장 프로그램 버전
보내지 않는 것: 기사 본문, 사용자를 알아볼 수 있는 어떤 것도

- 안내 두세 줄, 동의 버튼 글자, 거절 버튼 글자
- 보내는 항목을 **구체적으로** 적어 주세요. "일부 정보" 같은 뭉뚱그린 말은 쓰지 마세요

# 돌려줄 형식

각 항목마다 **후보를 3개씩** 주세요. 고르는 것은 제가 합니다.
후보마다 어떤 느낌을 노렸는지 한 줄로 덧붙여 주세요.

마지막에, 당신이 쓴 문구 중 **위 전제를 어길 뻔했던 것**이 있으면 알려 주세요.
````

   ```bash

   ```

   걸리는 것이 있으면 그 문구는 쓰지 않는다. (이 검사는 GE-16 에서 테스트로 만든다)
4. 돌린 날짜·모델(`claude-sonnet-5-5`)·후보 수·고른 이유를 [`docs/ai-log/`](../../docs/ai-log/) 에 적는다

# 2차 — 신호가 없는 항목의 문구 (GE-16 후속)

1차에서 항목마다 **"신호가 있을 때"** 와 **"판단하지 못했을 때"** 만 받았다.
**"살펴봤고 신호가 없었을 때"** 가 빠져서, 지금은 그런 항목을 배지 상세에서 **숨기고** 있다.

전부 보여 주면 사용자가 **무엇을 검사했는지** 알 수 있고, ⚪ 항목도 맥락 속에서 읽힌다.
그래서 일곱 항목의 "신호 없음" 한 줄을 받는다.

> **1차에서 고른 문구를 프롬프트에 함께 넣는다.** 새 대화에서 돌리면 말투가 어긋난다.
