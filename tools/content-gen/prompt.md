## 1. 배지 5단계 — 이름과 설명

기사 오른쪽 아래에 뜨는 작은 상자입니다. 이름은 한 줄에 들어가야 합니다.

| 상태 | 언제 | 지금 임시로 쓰는 말 |
| --- | --- | --- |

- 설명: 각 한 문장, 40자 이내
- SAFE 가 "이 기사는 믿을 만합니다" 로 읽히면 안 됩니다. **신호를 못 찾았을 뿐**입니다
- 다섯이 서로 뚜렷이 구분돼야 합니다

## 2. 판단 항목 7개 — 사용자용 이름과 "걸린 이유" 설명

배지를 누르면 어떤 항목이 걸렸는지 보여 줍니다. **지금은 영어 코드 이름이 그대로 보입니다.**

각 항목마다 세 가지를 써 주세요.
  (가) 사용자용 이름 — 12자 이내
  (나) 신호가 있을 때 보여 줄 한 줄 — 35자 이내
  (다) 판단하지 못했을 때 보여 줄 한 줄 — 35자 이내

| 코드 이름 | 무엇을 보는가 |
| --- | --- |
| source_citation | 본문이 주장의 출처를 밝히는 방식. 기관명·실명이 있는지, "전문가에 따르면" 처럼 이름이 빠졌는지, 아예 없는지 |
| headline_body_match | 제목이 전하는 내용이 본문과 맞는지. 어긋나는지, 일부만 반영했는지 |
| clickbait_headline | 제목이 내용을 감추거나("그 이유는") 부풀리는지("충격", "역대급") |
| spread_inducement | 글이 퍼뜨리라고 재촉하는지. "꼭 공유하세요" 같은 표현 |
| emotional_language | 분노·공포·혐오를 자극하는 표현을 얼마나 강하게 쓰는지 |
| ai_style_signal | 기계가 생성한 글에서 흔한 문체 특징이 보이는지. **글의 진위와는 별개입니다** |
| unverifiable_claim | 근거를 밝히지 않고 단정한 문장이 얼마나 있는지 |

- ai_style_signal 은 특히 조심해 주세요. "AI 가 썼다" 고 단정하면 안 됩니다
- "출처가 없습니다" 보다 "출처를 찾지 못했습니다" 쪽이 맞습니다. 우리가 못 본 것일 수 있습니다

## 3. 판단하지 못했을 때 (⚪)

왜 판단하지 못했는지 사용자에게 구분해서 알려 주지 않습니다. 이유가 무엇이든 한 가지 문구입니다.

- 제목 한 줄 (15자 이내) 과 설명 한 줄 (50자 이내)
- **사과가 아니라 설명입니다.** 오류 메시지처럼 보이면 안 됩니다
- "모르겠다" 를 솔직하게 말하는 것이 이 제품의 미덕이라는 느낌이면 좋겠습니다

## 4. 공유 직전 알림

주의 신호가 뚜렷한(CAUTION) 기사를 공유하거나 주소를 복사하려 할 때 뜹니다.

- 한 문장, 45자 이내. 닫기 버튼의 글자도 함께
- **공유를 막지 않습니다.** 막는 말투, 겁주는 말투를 쓰지 마세요
- "정말 공유하시겠습니까?" 같은 되묻는 말투도 피해 주세요. 알리기만 합니다

## 5. 피드백 동의 안내

판단이 틀렸다고 사용자가 알려 줄 수 있습니다. 보내기 전에 **무엇을 보내는지** 알려야 합니다.

보내는 것: 기사 주소, 화면에 떴던 판단 결과, 사용자가 맞다고 본 판단, 확장 프로그램 버전
보내지 않는 것: 기사 본문, 사용자를 알아볼 수 있는 어떤 것도

- 안내 두세 줄, 동의 버튼 글자, 거절 버튼 글자
- 보내는 항목을 **구체적으로** 적어 주세요. "일부 정보" 같은 뭉뚱그린 말은 쓰지 마세요
