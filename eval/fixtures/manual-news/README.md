# 선택 검사 수동 테스트 기사 45건

브라우저 확장 프로그램의 선택 검사를 같은 글로 재현하기 위한 정적 자료다. 실제 언론사 기사와 정식 GE-13 평가 세트에 포함하지 않는다.

## 구성

| 분류 | 건수 | 설명 |
| --- | --- | --- |
| 실존 인물 | 15 | 이름만 차용한 허구 기사 |
| 실제 지명·기관·법인 | 15 | 지명 5, 기관·단체 5, 법인 5. 사건·행사는 허구 |
| 과장 제목·사소한 내용 | 5 | 물병을 가져오는 등 작은 행동. 상황은 허구 |
| 과장 제목·사실 기반 | 5 | 공식 출처를 확인해 요약한 과거 기록 |
| 과장 제목·허구 내용 | 5 | 과장된 제목으로 허구의 문화 행사 등을 전달 |

허구 40건, 사실 기반 5건이다. 글은 Codex로 새로 작성했으며 실제 기사 전문이나 실제 인물의 발언을 복제하지 않았다. 사실 기반 5건에는 확인일과 공식 출처를 연결했다. 제목은 시험용으로 작성했고, 원출처의 제목을 옮긴 것이 아니다. 사실 기반이라는 표시는 주요 본문 사실의 출처 확인을 뜻하며 독립 검수된 정답 라벨은 아니다.

## 크롬에서 사용

1. 저장소를 내려받고 이 폴더의 [index.html](index.html)을 크롬에서 직접 연다. 서버나 빌드 없이 쓸 수 있다.
2. 분류와 기사를 고른다.
3. **제목·본문 선택**, **제목만 선택**, **본문만 선택** 중 하나를 누른다.
4. 선택된 글 위에서 우클릭하고 GenuEarly 검사 메뉴를 고른다.

선택 검사 결과는 자동 기사 검사 결과와 다를 수 있다. 허구라는 이유만으로 특정 배지 색을 정답으로 요구하지 않는다.

## 자동 기사 검사(①)도 해 보려면 — 개발 빌드

위 ③ 선택 검사는 배포본으로 바로 된다. **①(제목·본문을 읽어 배지를 띄우는 것)은 개발 빌드가 필요하다.**

```bash
npm run build -w @genuearly/extension -- --mode development
```

`apps/extension/.output/chrome-mv3-dev` 를 `chrome://extensions` 에서 **압축해제된 확장 프로그램으로 로드**하고, 그 카드의 **"파일 URL에 대한 액세스 허용"** 을 켠다. 그러면 이 폴더의 기사 페이지를 그냥 열어도 오른쪽 아래에 배지가 뜬다.

`http://localhost` 로 띄워도 된다 (포트는 아무거나).

```bash
npx --yes serve eval/fixtures/manual-news
```

**배포본에는 `file://`·`localhost` 권한이 들어가지 않는다.** 개발 빌드에서만 더해지고, `apps/extension/tests/manifest.test.ts` 가 빌드된 배포 manifest 와 콘텐츠 스크립트 번들에 그 주소가 없는지 본다.

### 이 자료로 확인할 수 있는 것과 없는 것

| 기능 | 되나 | 비고 |
| --- | --- | --- |
| ① 기사 배지 | 된다 | 본문 추출, 일곱 항목 판정, 배지 단계, 팝업, 심층 분석 |
| ② 목록 표시 | 된다 | [index.html](index.html)과 분류 목록에서 제목 옆에 붙는다. 기사 페이지에서는 돌지 않는다 — 읽는 중에 끼어들기 때문이다 |
| ③ 선택 검사 | 된다 | 배포본으로도 된다 |
| 공개 기록 리포트 | 된다 | 아래 "시험용 발행일" 참고 |

### 시험용 발행일

리포트는 기사 날짜가 없으면 만들지 않는다 — 날짜 없이 주변 기록을 맞추면 "같은 사안" 인지 알 수 없어 거짓 안심이 되기 때문이다. 그래서 각 기사에 **시험용 발행일**을 넣었다. `<meta property="article:published_time">` 과 본문 위 안내줄에 함께 적힌다.

**실제 날짜가 아니다.** 2026-09-01 부터 전체 45건의 자리 순서대로 하루씩 민 값이고, 같은 기사는 늘 같은 날짜가 나온다 (`build.cjs` 의 `mockDate`). `new Date()` 를 쓰면 재생성할 때마다 49개 파일이 통째로 바뀌어 diff 를 읽을 수 없다.

리포트가 만들어지기는 하지만 **허구 기사라 주변 기록이 거의 잡히지 않는다.** "기록을 찾지 못했습니다" 로 끝나는 것이 정상이고, 그 경로를 밟아 보는 것이 목적이다.

추출이 되는지는 `apps/extension/tests/fixture-extract.test.ts` 가 45건 전부에 대해 검사한다. `build.cjs` 가 기사 페이지의 모양을 바꾸면 그 검사가 먼저 깨진다.

모든 페이지의 브라우저 제목과 상단·하단에 테스트 표시를 둔다. 허구 글은 실존 이름을 차용한 허구임을 명시한다. 선택 버튼은 안내문과 작성 정보를 제외한 요청 영역만 선택한다.

## 재생성과 검증

저장소 루트에서 실행한다.

```sh
node eval/fixtures/manual-news/build.cjs
npm ci -w @genuearly/extension --include-workspace-root
node eval/fixtures/manual-news/verify.mjs
git diff --exit-code -- eval/fixtures/manual-news
```

원본은 articles.json이며, 생성기는 같은 폴더의 HTML·manifest.json·controls.js를 갱신한다. 생성 검사는 45건과 15/15/15·5/5/5 분할, 링크, 이름 포함 여부, 선택 길이 상한, 사실 기반 출처를 확인한다. verify.mjs는 기존 개발 의존성 happy-dom으로 45개 기사 페이지의 선택 버튼 135개와 출처 링크를 검사한다. CI의 extension 작업에서 재생성 뒤 차이가 없는지도 확인한다.
