# 라벨링 기준 (평가 세트 v1)

평가 세트에 정답을 붙일 때 이 문서만 보고 판단한다. **라벨이 흔들리면 이후 모든 숫자가 무의미하다.**
세트 구성, 라벨 파일 형식, 라벨링 절차는 [README.md](README.md)에 있다.

- 기준 버전: **1.0.0** · 대상 질문 세트: [judgment-items.json](../../packages/shared/judgment-items.json) **1.1.0**
- 이 문서는 **라벨을 붙이기 전에 커밋한다.** 결과를 본 뒤에 기준을 고치면 원하는 숫자가 나온다
- 라벨링을 시작한 뒤에 기준을 고치면 버전을 올리고, 이미 붙인 라벨을 **전부** 다시 본다

---

## 1. 무엇에 라벨을 붙이는가

**"주의 신호가 있는가"에 붙인다. "가짜인가"에 붙이지 않는다.**

이 서비스는 진위를 단정하지 않는다 ([docs/product.md](../../docs/product.md) 2절).
정답도 같은 것을 물어야 한다. 그래서 다음은 **보지 않는다**.

| 보지 않는 것 | 왜 |
| --- | --- |
| 내용이 사실인지 (검색해서 확인하기) | 제품이 묻지 않는 것이다. 맞혀도 측정할 수 없다 |
| 언론사 이름, 정치 성향 | 출처 도메인은 코드가 따로 본다 ([docs/product.md](../../docs/product.md) 4절). 라벨에 섞이면 두 신호가 겹친다 |
| 사건 자체가 얼마나 끔찍하고 자극적인지 | 보는 것은 **글을 쓴 방식**이다 |
| 라벨러 본인이 기사 논조에 동의하는지 | |

**Jev 결과를 보기 전에** 라벨을 붙인다. 다른 라벨러의 라벨도 보지 않는다.

## 2. 라벨은 두 층이다

| 층 | 무엇 | 왜 따로 두나 |
| --- | --- | --- |
| **배지 정답** | 기사 전체를 읽고 "이 기사에 맞는 배지" 하나 | 제품 지표(오탐, 🔴 정확도)를 재는 기준 |
| **항목 정답** | 판단 항목마다 "맞는 보기" 하나 | GE-17에서 항목별 가중치를 정하려면 어느 항목이 틀렸는지 알아야 한다 |

**두 층을 서로 맞추려 하지 않는다.** 배지 정답은 항목 정답을 합산해서 만드는 것이 아니라 따로 판단한다.
항목 정의가 잘못돼 있으면 항목 정답으로는 그걸 잡을 수 없고, 배지 정답이 어긋나는 것으로만 드러난다.

## 3. 배지 정답

| 값 | 배지 | 언제 |
| --- | --- | --- |
| `clear` | 🟢 안심 | 읽고 나서 따로 확인해 볼 점이 떠오르지 않는다 |
| `neutral` | 🟡 확인 권장 | 공유하거나 믿기 전에 확인해 볼 점이 **하나** 있거나, 약한 신호가 여럿 있다 |
| `caution` | 🔴 주의 | 공유하거나 믿기 전에 확인이 **꼭** 필요하다. 아래 '주의 신호'가 **둘 이상 뚜렷하다** |

⚪ 판단 보류는 정답이 될 수 없다. 모델이 판단을 하지 않았다는 표시이지 기사의 성질이 아니다.

**주의 신호** — 4절 항목의 caution 쪽 보기와 같은 것이다.

- 주장의 출처를 전혀 밝히지 않는다
- 제목이 본문과 어긋난다
- 제목이 내용을 감추거나 부풀리는 데 중심을 둔다
- 독자에게 퍼뜨리라고 직접 요구한다
- 글 전체가 분노·공포·혐오를 일으키는 표현을 중심으로 짜여 있다 (`emotional_language` 등급 3)
- 사실을 단정하면서 근거를 대지 않는 문장이 글의 중심 주장을 이룬다

### 판단 규칙

1. **AI 문체는 그것만으로 🔴이 되지 못한다.** 기계로 쓴 진짜 기사가 많다 ([docs/product.md](../../docs/product.md) 4절 원칙). AI 문체만 뚜렷하면 많아야 🟡이다
2. **애매하면 한 단계 아래로 붙인다.** 🔴과 🟡 사이에서 망설이면 🟡이다. 멀쩡한 기사에 🔴을 붙이는 쪽이 대가가 크다 ([docs/product.md](../../docs/product.md) 5절)
3. 신호가 하나여도 **결정적**이면 🔴이다. 결정적인 것은 "출처 없는 단정 + 퍼뜨리기 재촉"처럼 두 신호가 한 주장에 겹친 경우뿐이다. 라벨 메모(`note`)에 이유를 적는다
4. 정상 보도의 형식(통신사 단신, 보도자료, 날씨·증시)은 짧고 출처가 하나뿐이어도 🟢이다

## 4. 항목 정답

값은 [judgment-items.json](../../packages/shared/judgment-items.json)의 보기 키를 그대로 쓴다. 그래야 Jev 답과 바로 비교된다.
**보기의 정의는 judgment-items.json의 `criteria`가 원본이다.** 여기에는 사람이 판단할 때 헷갈리는 자리만 적는다.

모든 항목에 공통으로 쓸 수 있는 값이 하나 더 있다.

- `na` — 그 항목이 볼 필드가 없거나 판단할 수 없다 (본문이 없는 포토·영상 기사의 `source_citation` 등). 사유를 `note`에 적는다

### `source_citation` — 본문이 출처를 어떻게 밝히나

| 값 | 신호 |
| --- | --- |
| `named_source` | 🟢 |
| `unnamed_source` | 🟡 |
| `no_source` | 🔴 |

- 실명 출처가 **주장의 근거로** 한 곳이라도 있으면 `named_source`다. 익명 출처가 함께 있어도 그렇다
- 기사를 쓴 기자 이름과 그 기사를 낸 언론사 이름은 출처가 아니다
- 이름 없이 따옴표만 있는 인용("…"라는 목소리가 나온다)은 `unnamed_source`다
- **헷갈리는 자리**: 실명이 있지만 주장과 상관없는 자리에만 나오는 경우(사진 설명, 행사 참석자 목록). 주장의 근거가 아니면 출처로 세지 않는다

### `headline_body_match` — 제목과 본문의 관계

| 값 | 신호 |
| --- | --- |
| `matches` | 🟢 |
| `partial` | 🟡 |
| `contradicts` | 🔴 |

- 제목의 **핵심 내용**은 주어와 서술어가 전하는 사건이나 주장이다. 말투와 길이는 보지 않는다
- 제목 내용이 본문에 그냥 **빠져 있으면** `partial`이다. 본문이 **반대되거나 다른 사실을 적어 두어야** `contradicts`다
- 본문의 "~할 수도 있다"를 제목이 "~한다"로 단정했으면 `partial`이다

### `clickbait_headline` — 제목이 낚시성인가

| 값 | 신호 |
| --- | --- |
| `plain` | 🟢 |
| `mild` | 🟡 |
| `strong` | 🔴 |

- **제목 글자만 본다.** 본문과 맞는지는 위 항목이 본다
- `[단독]`, `[속보]` 같은 말머리는 무시한다
- 따옴표 속 발언이 자극적이어도 제목이 **누가 무엇을 두고** 한 말인지 밝히면 `plain`이다
- 판가름: 제목만 읽고 **무엇에 관한 기사인지 알 수 있으면** 많아야 `mild`, 알 수 없으면 `strong`이다

### `spread_inducement` — 퍼뜨리라고 재촉하나

| 값 | 신호 |
| --- | --- |
| `no_spread` | 🟢 |
| `hinting` | 🟡 |
| `urging` | 🔴 |

- 언론사가 모든 기사에 붙이는 구독·좋아요 안내는 무시한다
- `urging`은 독자에게 공유·전달을 **직접 요구**할 때만이다. "모두가 알아야 할"은 `hinting`이다

### `emotional_language` — 감정 자극 표현의 세기 (0~3)

| 값 | 신호 |
| --- | --- |
| `0` 담담함 · `1` 약함 | 🟢 |
| `2` 강함 | 🟡 |
| `3` 매우 강함 | 🔴 |

> 등급별 신호 구분은 이 문서의 라벨링용 해석이다. 제품의 실제 점수 환산은 GE-17에서 측정으로 정한다.

- **기자의 서술만 본다.** 따옴표로 인용한 발언 속 감정 표현은 세지 않는다
- 사건이 참혹해도 담담한 낱말로 전하면 0이다
- 판가름: 감정 낱말을 지워도 글이 그대로 서면 1, 글의 뼈대가 무너지면 2 이상이다

### `ai_style_signal` — 기계 생성 문체 특징 (0~3)

| 값 | 신호 |
| --- | --- |
| `0` 드묾 · `1` 일부 | 🟢 |
| `2` 뚜렷함 · `3` 매우 뚜렷함 | 🟡 (단독으로 🔴이 되지 않는다) |

- **진위와 별개다.** 이 등급을 보고 배지 정답을 끌어올리지 않는다 (3절 판단 규칙 1)
- 보도자료, 단신, 날씨·증시 기사는 원래 정형적이다. 정형성 자체가 아니라 같은 틀의 반복, "결론적으로"식 정리, 사안과 동떨어진 일반론을 본다
- **가상 기사에 붙일 때 주의**: 우리가 AI로 만든 글이라는 것을 알고 있다. 아는 것을 지우고 **글자에 보이는 것만** 본다

### `unverifiable_claim` — 문장 단위 (30건만)

평가 세트 중 **문장 라벨 대상으로 정한 30건**에만 붙인다 ([README.md](README.md) 2절).
문장은 [split.mjs](../experiments/sentence-batching/split.mjs)가 나눈 그대로 쓴다. 나누는 방식이 바뀌면 번호가 어긋나므로 라벨 파일에 분리기 버전을 함께 적는다.

문장마다 두 값을 붙인다.

| 필드 | `true` | `false` |
| --- | --- | --- |
| `factual_assertion` | 일어난 일·수치·인과를 **확정된 사실로** 서술한다 | 의견, 전망, 추측, 전해 들은 말("~로 알려졌다"), 질문, 가정 |
| `named_basis` | 문장 **안에** 기관명, 실명, 문서 이름, 다른 언론사 이름이 근거로 적혀 있다 | 집단·직함으로만 가리키거나("관계자는") 근거 표현이 없다 |

- **그 문장의 글자만 본다.** 앞 문장에 출처가 있어도 이 문장 안에 없으면 `named_basis: false`다. Jev도 문장 하나만 받는다
- 인용 문장은 **옮겨진 내용**이 확정 서술인지로 판단한다

## 5. 메모(`note`)를 남기는 경우

- `na`를 붙였을 때
- 3절 판단 규칙 3으로 신호 하나에 🔴을 붙였을 때
- 이 문서로 판단이 안 서서 고민한 끝에 붙였을 때. **이런 메모가 쌓인 자리가 기준을 고칠 자리다**
