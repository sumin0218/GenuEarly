## 왜 있는가

**확장 프로그램에 API 키를 넣을 수 없기 때문이다.** 확장 프로그램은 설치한 사람 누구나 압축을 풀어 전부 읽을 수 있다. 난독화해도 소용없다.

그래서 키는 여기 환경변수에만 둔다. 확장 프로그램은 여기에 요청하고, 여기가 자기 키로 Jev를 부른다.

## 맡는 일

- Jev 호출 중계 (`POST /v1/systemone`)
- API 키 보관
- 레이트 리밋 대응 (429, 백오프, `retry-after`)
- 실패를 ⚪ 판단 보류로 바꿔서 돌려주기
- 오판 피드백 수집 (**사용자가 동의한 것만**)

## 맡지 않는 일

- **점수 합산과 단계 결정** — [../../packages/shared](../../packages/shared/)의 몫이다. 서버가 하든 확장이 하든 **로직의 원본은 거기 하나**다
- **사용자에게 보이는 문구** — [../../packages/content](../../packages/content/)에 있다. 서버가 문구를 만들어 보내지 않는다
- **기사 가져오기** — 아래 "열린 프록시 금지"를 본다

## 시크릿

- `JEV_API_KEY`는 **환경변수로만** 받는다. 코드, 설정 파일, 저장소, 로그, 응답 어디에도 넣지 않는다
- 변수 **이름**만 [.env.example](.env.example)에 값 없이 적는다
- `.env`를 커밋하지 않는다
- 에러 응답에 Jev의 원본 에러 본문을 그대로 싣지 않는다. 키나 내부 정보가 섞여 나올 수 있다 (CWE-209)
- 실수로 키를 올렸다면 **즉시 폐기하고 재발급한 뒤** 팀에 알린다

## 열린 프록시를 만들지 않는다

**클라이언트가 준 URL을 서버가 가져오게 하면 안 된다.** 그 순간 누구나 우리 서버를 통해 아무 주소나 긁을 수 있게 되고, 내부망 주소를 넣으면 SSRF가 된다 (CWE-918).

- 서버가 받는 것은 **확장 프로그램이 이미 추출한 텍스트**다. URL이 아니다
- 기사 본문 추출은 확장 프로그램이 사용자의 브라우저에서 한다. 사용자가 이미 보고 있는 페이지이기 때문이다

## 입력 검증

확장 프로그램이 검증했다고 믿지 않는다. 공개된 엔드포인트는 남도 부른다.

- 요청 본문 크기에 상한을 둔다. Jev의 컨텍스트 한도(요청당 64k 토큰)와 비용이 걸려 있다
- 질문 개수와 텍스트 길이에 상한을 둔다
- 판단 항목 이름이 [../../packages/shared](../../packages/shared/)에 정의된 것인지 확인한다. 임의의 프롬프트를 통과시키지 않는다 — **그러면 우리 키로 남이 Jev를 쓰는 셈이 된다**
- 레이트 리밋을 건다 (우리 서버 기준, Jev 한도와 별개로)
- CORS는 우리 확장 프로그램의 origin만 허용한다. `*`로 열어 두지 않는다

## Jev 호출

사실관계는 [../../docs/jev.md](../../docs/jev.md) 6절에 있다.

- **모델 버전을 고정해서 보낸다.** `jev-latest`가 아니라 `jev-1.13.0`. 별칭은 새 릴리스가 나오면 옮겨 가고, 우리는 확신도 임계값을 특정 버전에 맞춰 놓았다
- 응답의 `model` 필드를 **로그에 남긴다.** 어느 버전이 낸 결과인지 모르면 회귀를 추적할 수 없다
- **기사 하나의 판단 항목들을 요청 하나에 묶는다.** Jev는 `state`를 한 번 읽고 모든 질문을 병렬로 평가한다. 요청 수와 토큰 모두에 유리하다
- 기사 본문은 **`state`의 데이터 필드**에 넣는다. `instructions`에 이어 붙이지 않는다 ([../../docs/jev.md](../../docs/jev.md) 3절 ⑥)

## 실패를 다루는 방식

**실패는 ⚪ 판단 보류다.** 추측해서 단계를 만들지 않는다.

| 상황 | 하는 일 |
| --- | --- |
| 429 Too Many Requests | 백오프 재시도. `retry-after` 헤더가 있으면 그것을 지킨다. 그래도 안 되면 ⚪ |
| 타임아웃 | ⚪. 오래 기다리지 않는다. 늦은 배지는 없는 배지다 |
| 확신도 낮음 | ⚪ |
| 응답이 우리가 정한 보기 밖 | ⚪ |
| Jev 장애 | ⚪ |

- 이전 판단 결과를 대신 돌려주지 않는다
- 사용자에게 보이는 실패 문구는 서버가 만들지 않는다. **⚪라는 사실만** 돌려주고 문구는 확장 프로그램이 고른다

## 로그와 데이터

- **요청 본문을 영구 저장하지 않는다.** 기사 본문이 서버에 쌓이면 안 된다
- 로그에 기사 본문, URL 전체, 사용자 입력을 남기지 않는다 (CWE-532)
- 사용자를 식별할 수 있는 값을 만들거나 저장하지 않는다
- 피드백은 **동의한 것만** 받는다. 받은 것도 기사 본문 전체를 담지 않는다

## 테스트

- 429, 타임아웃, Jev 장애에서 ⚪가 나오는지
- 정의되지 않은 판단 항목 이름이 거절되는지
- 크기 상한을 넘는 요청이 거절되는지
- 허용하지 않은 origin이 거절되는지
- 응답 어디에도 키가 섞여 나오지 않는지
